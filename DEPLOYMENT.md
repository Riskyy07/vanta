# VANTA Production Deployment — no VS Code required

## Target architecture

- `vanta-web`: public Next.js web service
- `vanta-worker`: continuous ingestion worker
- `vanta-e2e-check`: 30-minute live E2E check
- `vanta-db`: managed PostgreSQL with connection pooling
- Blockscout Base Mainnet API (chain 8453)

Render is the prepared deployment target because its Blueprints can define web services, background workers, cron jobs, Postgres, environment variables, and health checks in one version-controlled file.

## Runtime secrets

Set these in Render, never in browser code and never under `NEXT_PUBLIC_*`:

- `BLOCKSCOUT_API_KEY`
- `VANTA_WALLETS`

`DATABASE_URL` is wired from the managed database in `render.yaml`. `VANTA_MONITORING_SECRET` is generated by Render for the web service.

## Browser-only deployment path

1. Create a GitHub repository named `vanta`.
2. From GitHub's web UI, upload the contents of this release package. No VS Code is required.
3. In Render, choose **New → Blueprint** and select the repository.
4. Render reads `render.yaml` and provisions the VANTA web service, worker, scheduled E2E check, and PostgreSQL.
5. Enter the Blockscout API key when Render prompts for `sync: false` secrets.
6. Enter one or more comma-separated Base wallet addresses in `VANTA_WALLETS`.
7. Deploy.
8. Confirm `/api/health` is HTTP 200 and reports `status: ok`.
9. Run the public smoke check with the resulting URL: `VANTA_PUBLIC_URL=https://YOUR-URL npm run public:smoke`.
10. Only declare launch complete after `npm run e2e:live` passes against real data and the public smoke check passes.

## Important

The current assistant environment cannot authenticate into the user's Render/GitHub accounts or create a third-party deployment on the user's behalf. The release package is deployment-ready, but the real deployment and secret entry are external account actions.

Deployment hardening note (2026-10-01): VANTA uses session-level PostgreSQL advisory locks in the ingestion worker, so the Render Blueprint uses a direct Postgres connection (`connectionString`) rather than PgBouncer transaction pooling.
